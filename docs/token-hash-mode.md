# Token 哈希存储 & Channel 密钥脱敏（同步文档）

## 一句话说明

1. 用户主动创建的 API Key 增加可选"哈希模式"：数据库只存密钥的 HMAC 哈希，明文仅在创建时返回一次；数据库/Redis 被盗也无法还原或使用密钥。原有明文模式完全保留，兼容所有存量集成。
2. 新增全局开关 `MASK_CHANNEL_KEYS`：开启后所有返回 Channel 的接口永远只返回密钥预览，不再返回完整渠道密钥。

## Token 哈希模式

| 项目 | 说明 |
|---|---|
| 适用范围 | 仅用户在控制台创建时勾选"安全模式"的 Key；默认仍是明文模式。Desktop 等自动创建的 Key 继续用明文模式（可重复获取），如需安全由 Desktop 侧自行定期轮转（例如每天） |
| 存储形态 | `Key` 列存 `h:` + HMAC-SHA256 哈希（64 位十六进制），另存 `KeyPreview`（前 6 位…后 4 位）用于列表识别。生成 Key 为 48 位随机字符且不含 `:`，两种形态不会混淆，唯一索引保持有效 |
| 盐 | **固定内置盐**（编译进代码的 HMAC key）。目的只是防彩虹表/预计算；密钥本身 48 位随机（约 285 bit），离线碰撞在计算上不可行，因此无需 per-token 盐（与"按 Key 直查数据库"互斥）也无需可配置盐 |
| 认证 | 收到 Key 后算一次 HMAC（约 1µs/次）按唯一哈希槽位查缓存；回源用 `key = ? OR key = hash(?)` 一条查询覆盖两种存储形态。两种模式无缝共存，无需迁移存量数据 |
| 缓存 | 本地/Redis 缓存**一律以哈希为键**（含明文模式存量 Key）：明文不再出现在任何缓存键名中，Redis 泄露也无法直接得到可用 Key。旧的明文槽位条目升级后不再读取，数分钟内自然过期 |
| 明文可见性 | 创建/轮转响应返回完整 Key 一次；之后列表、详情接口只返回 `KeyPreview`，永不返回明文，也不返回哈希本身 |
| 轮转 | 新增 `POST /api/tokens/{id}/rotate` 与组版 `POST /api/token/{group}/{id}/rotate`：生成新 Key、旧 Key 立即失效；请求体可选 `{mode: "hash" \| "plain"}`，**可同时切换存储模式**（明文→哈希，或哈希→明文），缺省保持当前模式，还可同时设置 `expired_at` 到期时间（适合"轮转出来的 Key 只活一天"这类用法）。忘记复制哈希模式 Key 的唯一补救方式 |

## Channel 密钥脱敏

- 环境变量 `MASK_CHANNEL_KEYS=true`（默认关闭）。
- 开启后：所有返回 Channel 的接口（列表/详情/创建/更新/批量查询等）中 `key` 字段一律替换为预览（前 6 位…后 4 位），包括创建/更新这类此前会回显完整密钥的响应。
- 服务端仍存完整渠道密钥（上游请求需要），仅出参脱敏；关闭开关即恢复原行为。

## 运营注意

1. 固定盐没有丢失风险、没有跨实例同步问题，升级/回滚均不涉及盐管理。
2. 升级到"全量哈希槽位"版本时：存量明文缓存条目在数分钟 TTL 内自然过期，期间新旧实例缓存互不命中、回源略有上升，属预期现象，无需处理。
3. 哈希模式的 Key 泄露或忘记复制：只能通过轮转换新 Key（可顺带切回明文模式）。
4. 开启 `MASK_CHANNEL_KEYS` 前，请确认没有依赖创建/更新接口回显密钥的自动化流程（如有，改为从提交时的入参自行记录）。
5. Sealos Desktop 等需要反复读取明文 Key 的产品不受影响；建议 Desktop 侧对自动创建的 Key 定期调用轮转接口。

## 用户感知

- 创建时勾选"安全模式" → 弹窗展示完整 Key，提示"仅显示一次" → 复制后关闭，此后界面只显示预览。
- "轮转密钥"入口可选保持/切换存储模式，新 Key 同样只展示一次。
- 明文模式的 Key 行为与现在完全一致。
- `MASK_CHANNEL_KEYS` 开启后，渠道密钥在界面上同样只显示预览。
